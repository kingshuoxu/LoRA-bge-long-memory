# LoRA-bge-long-memory

用 **bge 检索 + LoRA 专家池**给稠密 LLM 做"权重级长期记忆"：事实被训练进独立的 LoRA 专家（权重即记忆，不占用 prompt / KV cache)，由 bge 语义索引自动路由挂载。在 Qwen2.5-0.5B / 1.5B 双基座上都跑通了全量验证。

## 总体思想

LLM 的"长期记忆"目前主要有两种形态，都有硬伤：

- **prompt / 上下文记忆**：塞进 context，占 token、随窗口丢弃，成本随长度增长；
- **RAG**：检索的是文本，模型要"现场阅读"才能回答——本质还是 prompt 记忆；
- **直接微调写入**：权重即记忆，但灾难性遗忘（学新忘旧），且动了基座、无法管理单条记忆。

本仓库验证第三条路线：**把记忆写进权重，但每批记忆隔离成一个独立的 LoRA 专家文件**：

```
写入: 新事实 → 训练一个 LoRA 专家 → 注册进 bge 索引
        ↑ 自动门(bge 去重 + QA 自答一致性): 拒重复/已知,误写率 72%→16%
读取: 问题 → bge 检索 top-1 → 相似度 > τ=0.6 → 挂载对应 LoRA → 生成
        ↑ 低于阈值 → 原生基座回答(通用能力零退化)
```

记忆从"边看边答"(RAG）变成"早已记住"（权重）；每条记忆 = 一个几 MB 的 adapter 文件，可增删、备份、分发、组合、版本化，且完全不动基座——这是 prompt 记忆和全量微调都不具备的工程性质。

## 这项工作的真正意义

**架构不是首创** "LoRA 专家池 + 检索路由"在学界已有先行/并行工作（参数化 RAG 的 P-RAG/DyPRAG 系列、Adaptive Minds、LoRAMoE 等，见下节）。本仓库的价值不在提出新架构，而在三件学术论文通常不做或不展开的事：

1. **用反事实对照给出因果证据**。"参数隔离防遗忘"很多论文当常识引用，这里给出了干净的对照：同一个 LoRA、同样的数据、同样的训练预算，顺序续训后旧批记忆只剩 **0~12%**；拆成专家后 **82~100%**(G2 对照，`docs/experiment-results.md` §7)。这是"每批经验一个专家"架构存在的定量理由。
2. **把自动写入门做到可用，并完整记录信号换代过程**。perplexity 门误写 72%（信号太弱，AUC 仅 0.876)→ QA 自答门误写 16%（让基座自答、答错才写）。途中修正了两个评估陷阱："读阈值误当写阈值"（首轮召回仅 16.8%）和"误激活率冤案"（激活且答对不算损伤；真实有效损伤仅 1/20)(§9)。
3. **诚实标定边界与上限**。bge 单层路由实测 200 专家 / 1 万条事实零错误；τ∈[0.55,0.95] 安全域内行为不变；单 LoRA(r=32）装 1000 条事实不饱和。同时暴露两个真实失效模式——**条件反射边界**（换问法可能失配）与**晚期发散**（收敛后继续训练会擦除记忆，早停是记忆生命周期管理的一部分，§4)。

## 思想来源与参考工作

设计直接借用了以下工作:

| 来源 | 借用了什么 |
|---|---|
| **Lifelong-MoE / LoRAMoE / MoRAL**(LoRA-MoE 持续学习线） | 核心载体：新经验 → 新 LoRA 专家，参数隔离天然防覆盖 |
| **Titans / ATLAS**(Google，测试时参数记忆） | 写入控制：surprise（意外度）决定写不写——本仓库落地为 bge 去重 + QA 自答门 |
| **P-RAG → DyPRAG → Latent Routing**（参数化 RAG 线） | 并行实践：每篇文档一个 LoRA、推理时检索 adapter 挂载；证明同架构有效 |
| **Adaptive Minds / PEAM / Selective Parametric Consolidation** | 并行实践：agent 场景"每域/每经验一个 LoRA + 语义路由" |
| **LoraRetriever / PMDRouter** | LoRA 池的输入感知检索与路由基准（本仓库用外挂 bge；内生路由是下一步） |
| **Sleep-time Compute / Nested Learning (HOPE)** | 下一步方向：sleep-time 蒸馏合并专家、按更新频率分层记忆 |
| **Memory Layers at Scale / MoVE**(Meta 等） | 参数记忆规模化的形态参照 |

与这些工作的关系：本仓库不追求更大规模、不做学习型路由，而是补上它们普遍省略的**对照实验与边界标定**(G2 反事实、写门信号校准、τ 安全域、路由压测、双基座规模稳定性）。

| H1 记忆写入（事实 recall) | **100.0%** | **100%** |

| 通用能力（CMMLU 10 科×30 题，router vs base) | **零退化 (30.0%)** | **零退化** |
| 单 LoRA 容量（r=32) | ≥1000 条不饱和 | — |

| 记忆删除与实体守卫（淘汰专家，§14 & §15.1) | **100% 回退基座，0% 交叉误射** | — |
| 端到端自然语言抽取自进化 (§15.3) | **100% 抽取与自验通过** | — |

关键结论：

- **方案成立**：外挂 LoRA 池可以实现权重级长期记忆——能写入、有选择性、不遗忘、可路由、可自动写入、不伤通用能力；0.5B→1.5B 方向一致（规模稳定）。
- **"不遗忘"来自参数隔离本身**(G2 对照），不是任务简单或训练技巧。
- **安全域很宽**:bge 相似度 τ∈[0.55, 0.95] 内读取路由与写门行为不变（事实 query≈0.70–0.88，通用 query≤0.54)，阈值不是玄学。
- **条件反射机制（已量化，§13)**：训练问法间零差距（93%+)，训练没见过的句式 88.8%；掉点在生成端的属性绑定（"老大/招牌"这类口语词弱化属性线索→答错属性），路由端零失配。
- **训练有"晚期发散"坑**：收敛后继续训练会擦除已写入的记忆，需早停（§4)。

全部数字、失败迭代与阈值标定见 `docs/experiment-results.md`(14 节主文档）；设计动机见 `docs/experiment-design.md`。

## 真实问法下的实体守卫

V3 的实体守卫把问句抽成一个字符串，再和专家名单做精确比对。名单本身是从 `key_texts` 里「公司」前面整段切下来的，里面有「去哪座城市可以找到塔缪格雷」这种整句；抽不出实体时又退回子串匹配，「莫特」「温特」会撞进更长的名字。原模板上删掉专家后误射是 0/400。换一套模板就不成立：「塔佐巴洛集团的旗舰产品是什么?」会抽出「塔佐巴洛集团」，对不上在册的「塔佐巴洛」。

现在分五步。实体名单和边界仍是字符串查找；事实闸在实体选定后再做一次 bge 比较：

1. 从 `key_texts` 收实体时剥掉问句前缀和「这家 / 把 / 集团 / 公司」，名单只留实体名。
2. 守卫拿在册实体做最长匹配，左右两侧不能是名字音节。所以「塔佐巴洛集团」「你好，…公司」能对上「塔佐巴洛」，「莫特」对不上「巴莫特」。
3. 实体优先路由：问句里只有一个在册实体，而且名字旁边 12 字内有公司类线索（公司、集团、董事长、旗舰、成立……），就直接去那家专家，不再看 bge top-1。点了好几家时，能从「想问的是 / 说说 / 先别说」确定主语、并且主语仍在册，才去那家；比较句（「相比」）或主语已经不在册，就弃权回基座。一个在册实体都没有，才退回 bge top-1 ≥ τ 且守卫通过。
4. 事实闸：路由已经选定实体之后，判断这条事实的原文答不答得了这句问话。答不了就弃权，回基座。比较的是掩掉实体名之后的 bge 向量，不靠手写的属性词表。详见下面「事实闸」。
5. 两字名左右必须是问句套话里出现过的字。所以「请问菲尔公司」仍命中「菲尔」，「埃菲尔」「福克纳」里的「菲尔」「克纳」不再命中。

错字、缺字、多一个音节的近名不做模糊匹配。没有重训专家。多套释义键和 bge-reranker 都没有加。

评测脚本 `scripts/eval_entity_guard_realistic.py`，题目在 `data_guard/realistic_queries.jsonl`，另加 `data/` 的原模板和 `PARA_QUESTIONS`。τ=0.6。下表三列依次是：旧正则守卫 + bge top-1、边界守卫 + bge top-1、实体优先。正确路由 = 挂上了这条事实所属的专家。删除后误射 = 去掉该专家后仍挂上了别人。

| 问法 | 题数 | 正确路由召回（正则 → 边界+bge → 实体优先） | 删除后误射（正则 → 边界+bge → 实体优先） |
|---|---:|---|---|
| 原模板 | 2000 | 2000 → 2000 → **2000** | 0 → 0 → **0** |
| 未见口语 | 500 | 500 → 500 → **500** | 0 → 0 → **0** |
| 集团 / 企业 / 股份 | 1000 | 115 → 529 → **1000** | 8 → 0 → **0** |
| 职务（董事长等） | 1000 | 621 → 849 → **1000** | 0 → 0 → **0** |
| 口语 | 1750 | 1225 → 1225 → **1750** | 65 → 0 → **0** |
| 长上下文 | 1000 | 389 → 502 → **1000** | 31 → 0 → **0** |
| **真实单实体合计** | **4750** | **2350 → 3105 → 4750** | **104 → 0 → 0** |

向量 top-1（≥ τ）在真实单实体上是 3105/4750，纯向量删专家后会误射 4706/4750。边界守卫把误射压到 0，召回停在 top-1。实体优先把召回补到 4750/4750，五个专家各自删掉后 950 题误射仍是 0。这 4750 里，问的属性和这条事实训练属性一致的有 1045 题，bge top-1 已经是 1045/1045；实体优先多出来的 1645 题问的是没训过的属性。

| 问法 | 题数 | 路由误激活（正则 → 边界+bge → 实体优先） |
|---|---:|---|
| 错字 | 500 | 15 → 0 → **0** |
| 残名 | 332 | 6 → 0 → **0** |
| 近名（多一个音节） | 500 | 133 → 0 → **0** |
| 常识（含原 20 题） | 35 | 0 → 0 → **0** |

常识题最高相似度 0.556。CMMLU 全量 67 科 11582 条题干重跑了路由（没有做生成）：最高相似度 0.687，其中 21 条 ≥ 0.6，边界守卫和实体优先的激活都是 **0**。两字名会嵌在真实词里，例如「埃菲尔」里的「菲尔」、「福克纳」里的「克纳」。题干「著名的埃菲尔铁塔位于」对「菲尔」那家专家的相似度是 0.610，另一家是 0.613，所以边界路径这次没挂上；实体优先要求名字旁边有公司类线索，这条也不挂。

双实体 750 题。正则守卫正确路由 180、删除后误射 267；边界守卫是 273 和 383（383 都打到问句里另一家）。实体优先把「想问的是 / 说说」那 500 题直达主语，250 条「相比」弃权；删掉主语那家之后误射 **0**。

抽样生成用 Qwen2.5-0.5B-Instruct，CPU、float32，`max_new_tokens=40`，种子 20261022。每种问法抽 50 条**问的就是这条事实训练过的属性**（职务按 CEO 计；「头衔是董事长还是总裁」「干啥的」没有唯一答案，没放进这 50 条）。另抽 50 条比较句，常识题 35 条全跑。命中 = `gold.rstrip("年")` 出现在回答里。三列是纯基座、边界守卫+bge、实体优先。

| 问法 | 抽样 | 基座 | 边界守卫+bge | 实体优先 |
|---|---:|---:|---:|---:|
| 原模板 | 50 | 0/50 | 50/50 | **50/50** |
| 集团 / 企业 / 股份 | 50 | 0/50 | 50/50 | **50/50** |
| 职务（问到 CEO 事实） | 50 | 0/50 | 50/50 | **50/50** |
| 口语 | 50 | 0/50 | 50/50 | **50/50** |
| 长上下文 | 50 | 0/50 | 50/50 | **50/50** |
| 双实体（问到已存属性） | 50 | 0/50 | 33/50 | **40/50** |
| 常识（20 条有标准答案） | 20 | 18/20 | 18/20 | **18/20** |

单实体、问到已存属性时，边界守卫已经会挂对专家，所以两边记忆都是 50/50。双实体里实体优先挂上了全部 50 家主语，答对 40；另外 10 条挂对了专家，嘴里却是同一专家里另一家的事实。比较句 50 条：实体优先挂载 0，回答里带出某条已存事实的次数是 1/50，和纯基座一样；边界守卫挂了 39 条，带出已存事实 10/50。常识题两边激活都是 0，没有有效损伤。基座自己答错的两题是「人体最大的器官」（答成肝脏）和「光速」（答了 299,792 公里，标准答案写的是「30万」）。

另外抽了 8 条问的不是已存属性的单实体题。实体优先会把专家挂上，模型就按问句的属性类型，从同一批事实里报出另一家的人名、年份或型号。例如「菲希塔希集团的旗舰产品是什么?」这条只训过 CEO，回答是「达鲁莱先生」。事实闸就是为了拦住这种回答。

### 事实闸

关键词属性闸已去掉。那一版把问句分成 CEO / 成立年份 / 总部城市 / 旗舰产品四类，靠手写词表对上 `entity_attrs.json` 里的类别。类别表覆盖不了开放域里任意一条事实，所以换掉。

现在每个专家目录是 `fact_memory.json`：实体、陈述句、写入时的问句、答案原文，没有属性类别。推理时把问句和库里所有在册实体都换成同一个占位符「某」，陈述句里的答案换成「某值」，用已经加载的 bge-small-zh-v1.5 做余弦。接受要同时满足两件事：和这条事实的最高相似度 ≥ τ，并且不低于库里其他不同事实。τ 写在 `experts/fact_gate.json`，推理时不再重算。

τ 只在两类事实上校准：CEO 和成立年份，而且只用 `PARA_QUESTIONS` 那两句未见口语。四句里最低的是「诶，某公司现在的老大叫什么来着?」对 CEO 问句库的 0.622，文件里记 0.622。同一组上，拿另一类的 PARA 问法当负例，4/4 弃权。原模板问句（和库里原文相同）是 2000/2000，没有拿来抬高 τ。掩掉实体之后，同一句模板对所有实体的分数相同，所以这 4 句就代表这两类的全部实体。

| 调参：CEO / 成立年份的 PARA，问的就是这条事实 | 接受 244/244 |
| 调参：这两类互相当负例（PARA） | 弃权 4/4 |
| 留出问法：CEO / 成立年份的真实模板，问的就是这条事实 | 接受 598/656 |
| 留出问法：这两类互相问错 | 弃权 686/686 |
| 留出属性：总部城市 / 旗舰产品的 PARA | 接受 256/256 |
| 留出属性：这两类的真实模板，问的就是这条事实 | 接受 510/510 |

598/656 里少的 58 条全是「{实体}集团的创始人是哪一位?」。它和 CEO 问句库的相似度是 0.577，比某条年份事实的 0.583 还低，也低于 τ。写入的原文是「首席执行官」，闸没有把「创始人」当成同一个类别。要把这句放进来，τ 得降到 0.577 以下；那样「是干啥的」也会过（0.580，而且比其他事实更近）。所以 τ 停在调参集的 0.622。

### 改写问句和窄带交叉编码器

「集团的创始人是哪一位」对不上「首席执行官」，职务抽样因此是 30/50。试了两种不写属性词表的补法，阈值仍然只在 CEO / 成立年份的 PARA 问法上取。默认仍是上面的双编码器闸，这两种都没有开。

**(A) 写入时改写问句。** 基座 Qwen2.5-0.5B-Instruct 按事实自己的陈述句和已有问法，逐句换一种说法。提示里没有属性类别，也没有评测题。和留出评测题在去掉实体名、标点之后完全相同、把留出题原样包了一层、或编辑距离不超过 3 的，都丢掉。350 条事实（250 条训练集 + 100 条开放域）生成 1035 句，丢掉 53 句近复制和 1 句新的拉丁词（CFO）。留下的句子里没有「某集团的创始人是哪一位」，也没有开放域那两句留出问法（「创始人是哪所学校毕业的」「创始人的毕业院校是什么」）。同一句改写若被几种陈述句都生成了，只留给生成它的实体更多的那一种；然后这种陈述句下的每个实体都带上这些问句。另外用四句调参正例做了检查：改写如果比正确事实更靠近这四句，就从错误的那组里丢掉（257 条）。写入耗时 **1379 秒 / 350 条，平均 3.9 秒/条**（CPU，float32）。

**(B) 窄带里的 bge-reranker-base。** 只给双编码器已经拒绝、又离决策边界不远的问句打分。带宽是留一问法的最大落差 0.1643（拿掉「老大」之后 τ 会升到 0.786，这句自己落在下面 0.164）。切分 5.04 是 PARA 正例里「陈述句胜过另一条事实」的最低分。双边复议会把「老大」翻成弃权：CEO 陈述句得分 -1.41，年份陈述句 2.98，所以已经接受的不再翻案。「创始人是哪一位」对 CEO 陈述句只有 -0.62，低于切分，也低于调参负例的 2.98。把切分降到能捞回这句，「老大」问在年份事实上就会被接受。

## 局限

专家更新/删除已支持（§14)：同实体改值 → 实体键定位 + 重训替换，删除 = 移除文件。删除后的单实体问法不再误射；一句里两家都点到名时，比较句和已删除的主语会弃权，说得清主语才去那一家。问句和该实体已存事实对不上时路由弃权，回基座（见上节）。「创始人」这种和写入问句差得较远的说法会弃权，职务抽样因此是 30/50。写入时用基座模型改写问句能把这 58 条补上，但「老板叫什么名字」会从 CEO 事实掉到城市事实上，口语抽样从 50/50 降到 37/50，所以默认没有打开。库里从没有过的关系，若和某条已存事实的掩码相似度仍超过 τ（母校问法对年份 0.636、竞争对手问法对 CEO 0.657），还是会挂上专家。窄带交叉编码器在调参集上能用的切分捞不回「创始人」。事实需以问答对形式写入，陈述句→问题的自动转换未做；自答信号存在"瞎猜猜中"的理论风险（250 条中观测到 1 例）；路由是外挂 bge 检索加实体字符串，真 MoE 层内路由（OLMoE 式）是下一步方向，未实现。双实体在事实对得上时仍会把同一专家里另一家的事实说出来（抽样 40/50）。两字名靠左右套话字挡住了「埃菲尔 / 福克纳」，左右正好是允许字的真实词仍可能被当成实体。
